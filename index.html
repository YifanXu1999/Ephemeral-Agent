01 — 项目概述

瞬态主体：
智能体的新物种

Ephemeral OS 建立在一个颠覆性的核心理念之上—— 瞬态智能（Ephemeral Intelligence）： 让智能体「生于任务、终于任务」，彻底消灭认知过载与状态污染。

传统 AI 编程工具依赖一个长期运行的「全能大脑」。这就像强迫一个人同时 扮演架构师、开发者、测试员和项目经理——不可避免地陷入认知过载。 Ephemeral OS 的答案是：不让一个智能体变得无所不能， 而是让系统在正确的时间创建正确的智能体。

∞ 并发智能体上限

①
按需诞生

每个具体任务触发一个专精智能体的创建，携带精确上下文和明确目标出生。无冗余，无历史包袱。

②
专注执行

它只关心自己的任务——不需要管理全局状态，不需要记忆历史对话，不需要协调其他人。聚焦即力量。

③
使命完成即消亡

任务完成后，产出被系统收割，智能体优雅退出。不留任何需要维护的状态——资源永远不被浪费。

④
集体智慧永续

单个瞬态主体无记忆，但系统有集体智慧。每次任务的经验被永久沉淀，惠及所有未来的瞬态主体。

03 — 核心能力

四大系统创新

WORLD FIRST — 递归式瞬态智能体协作框架
3.1
多智能体编程框架 — AI 工程指挥部

用户只需描述高层目标（如「为电商平台添加购物车功能」），系统自动将其分解为可并行执行的任务图。

  • 目标驱动：自然语言目标 → 结构化任务图，无需手动分解
  • 瞬态分工：数据库专家、API 开发者、前端工程师、测试专家按需诞生
  • 层级递归：复杂任务展开为子任务，子协调器（本身也是瞬态主体）继续规划
  • 实时协作：所有瞬态主体共享运行环境，像真实团队一样感知彼此产出

类比：Copilot 是「AI 实习生」，Ephemeral OS 是「能随时召唤任意专家的 AI 工程指挥部」

WORLD FIRST — 多智能体共享实时沙盒
3.2
天眼模式（God's Eye Mode）— 共享沙盒

所有瞬态主体共享同一个实时沙盒环境，解决多智能体协作的可见性与一致性问题。

  • 统一视野：瞬态主体 A 创建数据模型，主体 B 立即可引用，零延迟同步
  • 实时代码分析：持续分析沙盒代码结构，提供准确符号表、依赖关系、类型信息
  • 安全隔离：独立沙盒实例，失败运行不会污染原始代码

瞬态主体不需要记忆——因为它能直接看到一切。环境本身就是最好的上下文。

WORLD FIRST — OCC 应用于多智能体代码协作
3.3
意图感知 OCC — 高并发 Agent Swarm

乐观并发控制：先做后校验，让并行成为默认而非例外。

  • 先做后校验：瞬态主体自由读写，系统在写入时自动检测冲突
  • 智能合并：不同区域的编辑自动合并，无需人工介入
  • 波次调度：依赖图中无前置约束的任务同时启动，最大化并行度
  • 弹性模型选择：轻量任务用快速模型，复杂任务用强力模型，动态分配

OCC 之于多智能体，就像 Git 乐观合并之于多人协作——并行是常态，锁是异常。

WORLD FIRST — 事件驱动取代传统 Harness Loop
3.4
Agentic Harness — 规划驱动架构
❌ 传统模式
计划 → 生成代码 → 评估结果 → 不满意？回到计划 → 再生成 → 再评估 ...
✓ EPHEMERAL OS
目标 → 智能规划（4阶段）→ 任务图持久化 → 瞬态主体并行执行 → 动态展开 → 自动收敛
  • 规划即产出：任务图持久化到数据库，系统重启后可从断点恢复
  • 事件驱动：没有 while-loop，每个主体完成后触发事件，系统自动启动下一波
  • JIT 动态展开：任务执行时再做细粒度分解——在正确的时间做正确的决策
  • 内建验证：每个规划阶段结束后专门验证工具检查结构和一致性

04 — 技术护城河

全栈系统，
六层纵深防御

市面上的多智能体框架大多停留在「调度层」。 Ephemeral OS 是从规划到沙盒的全栈系统，每一层都构成独立的竞争壁垒。

规划层
目标分解、任务图生成、JIT 动态展开、内建四阶段验证
调度层
依赖感知 DAG、波次并行调度、级联事件触发
执行层
瞬态主体完整生命周期管理，支持递归自我孵化
代码智能层
天眼系统六组件结构化索引：符号分析、影响评估、依赖追踪
并发层
AST 级 OCC + 三阶段提交（Read → Validate → Write），智能合并
环境层
天眼模式共享沙盒、三层 AST 缓存（L1/L2/L3）、安全隔离
系统在每次运行后自动总结经验，形成持续优化的知识库。 瞬态主体虽然「无记忆」，但系统有集体智慧—— 就像蚁群中的信息素，单只蚂蚁没有记忆，但蚁群的智慧在不断积累。
